# AD023 - empty-section

Tags: core, structure, references
Severity: info
Fixability: no.
Fix helper: Add body content, add a child section that belongs under this heading, or remove the empty section if it is only conversion/bookmark residue.

Description: Sections should contain body content or child sections.

Necessity: Asciidoctor allows empty sections. It also automatically creates IDs for sections by default, so an explicit anchor is not required for an empty section to become a linkable outline node. Empty sections are usually unfinished authoring structure or conversion/bookmark residue.

Rationale: The rendered output contains a visible heading, generated ID, and outline/TOC entry, but no body content under that node. That is not invalid AsciiDoc, so the rule is informational, but it is broadly useful cleanup for publishable technical documents.

Bad:

What's wrong: The `Empty` section creates a visible heading and link target with no body content and no child sections before the next sibling starts.

```adoc
== Empty

== Next
```

Good:

Expected: The section has body content.

```adoc
== Overview

Content.
```

Also good:

Expected: A container section may have child sections instead of direct body text.

```adoc
== Container

=== Child

Content.
```

AsciiDoc/Asciidoctor basis: Asciidoctor documents sections as implicit
enclosures that begin at a section title and end at the next sibling or ancestor
section. It also auto-generates IDs for sections unless `sectids` is unset, and
custom IDs are optional.

Rendering rationale: Asciidoctor emits no diagnostic for an empty section. The
HTML output still contains a section wrapper and heading ID, so readers and TOCs
can land on an empty node.

Implementation note: AD023 uses the normalized section model instead of scanning
raw heading and anchor lines. A section is considered non-empty when it has at
least one normalized child section or at least one normalized content block.
Explicit anchors are not required for the rule because ordinary sections already
have generated IDs by default.
