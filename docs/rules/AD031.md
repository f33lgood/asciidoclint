# AD031 - no-nested-link-text

Tags: links, conversion
Severity: warning
Fixability: no.
Fix helper: Replace the nested link markup with plain visible text, or split the sentence into separate links.

Necessity: Nested link macros or cross references inside visible link text do not produce a clean nested link in rendered AsciiDoc. They can produce invalid nested anchors, malformed labels, or escaped reference text.


Link text should not contain nested links or cross references.

Bad:

What's wrong: The outer link label contains another link macro. The cross-reference label contains a shorthand cross reference.

```adoc
link:https://example.com[link:https://nested.example[Nested]]

xref:target.adoc[<<target,Target>>]
```

Good:

Expected: Keep the outer link label as plain text, or split the content into separate links.

```adoc
link:https://example.com[Example]
```

AsciiDoc/Asciidoctor basis: The link macro documentation defines link text as
the attribute list of the link macro. It does not define nested links as a valid
authoring pattern. As with HTML, nested anchors are not useful rendered output.

Asciidoctor.js behavior: Local rendering confirms that
`link:https://example.com[link:https://nested.example[Nested]]` emits nested
`<a>` elements. `xref:target.adoc[<<target,Target>>]` renders the shorthand xref
text inside the outer xref label rather than creating a second clean link.

Parser ownership: AD031 uses a narrow source scanner because Asciidoctor parses
the outer link and does not emit diagnostics for the nested label content. The
scanner detects outer `link:`, `xref:`, and URL macro forms and checks their
visible text for nested `link:`, `xref:`, or shorthand `<<...>>` references.

Implementation note: AD031 skips protected blocks such as source, listing,
literal, passthrough, diagram, stem, and comment blocks. It does not report a
plain URL string inside link text unless that URL is written as an AsciiDoc URL
macro with its own bracketed label.
