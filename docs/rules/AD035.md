# AD035 - blank-after-block

Tags: `cleanup`, `blocks`
Severity: warning
Fixability: safe.
Fix helper: Insert one blank line after the closing block delimiter. This is the safe automatic fix emitted by asciidoclint.

Necessity: Asciidoctor accepts text immediately after a closing block delimiter, so this rule is not an error. The Asciidoctor documentation and recommended practices present delimited blocks as bounded source structures, and a blank line after the closing delimiter makes that boundary clear for maintainers and converters.


Structural block delimiters should be followed by a blank line.


Bad:

```asciidoc
====
example
====
Text
```

What's wrong: Asciidoctor can render this as a block followed by a paragraph,
but the source boundary is harder to scan and violates the recommended shape of
a clearly bounded delimited block.

Good:

```asciidoc
====
example
====

Text
```

Expected: The following paragraph remains outside the block and the source makes
that boundary explicit.

Rationale: this is an Asciidoctor-documented block boundary and paragraph
separation recommendation, not a known rendering failure. It stays a warning.

AsciiDoc/Asciidoctor basis: Asciidoctor documents delimited blocks as linewise
containers bounded by matching delimiters. The paragraph documentation says a
new paragraph is separated from the previous paragraph or block by at least one
empty line.

Asciidoctor.js behavior: Local rendering confirms that paragraph text
immediately after a closing delimiter usually renders as a following paragraph
without a parser diagnostic. The issue is source clarity and conformance to the
documented paragraph/block separation shape, not known output corruption.

Parser ownership: AD035 uses a source scanner because Asciidoctor parses the
block successfully and does not emit a diagnostic for the missing separator. The
scanner recognizes documented structural delimiter families, including longer
matching delimiter lines and table delimiter variants such as `|===`, `,===`,
`:===`, and `!===`.

Implementation note: AD035 skips protected block content, table cell content,
continuation lines, structural lines that can legally follow a block, comments,
conditionals, anchors, titles, block attributes, and list items. The safe fix
inserts one blank line after the closing delimiter.
