# AD012 - diagram-title

Tags: `core`, `diagram`
Severity: warning
Fixability: no.
Fix helper: Add a meaningful diagram title using `.Title` or `[title="..."]` above the diagram block metadata, or set `title="..."` in the diagram attribute list. Do not use generic placeholders such as `.Diagram`.

Necessity: A diagram block renders as a generated figure, but without a title it is hard to reference, review, or distinguish in long generated documents. Generic placeholder titles such as `.Diagram` do not identify the diagram purpose.


Diagram blocks should have a title, either as a `.Title` line or as an
AsciiDoc block title attribute such as `[title="..."]`.

Bad:

```asciidoc
[mermaid]
----
graph LR
----
```

Also bad:

```asciidoc
.Diagram
[mermaid]
----
graph LR
----
```

Good:

```asciidoc
.System flow
[mermaid]
----
graph LR
----
```

Also good:

```asciidoc
[title="Protected Data Base Address Low Register"]
[wavedrom, ,svg]
....
{reg: [{bits: 32, name: 'VALUE', attr: 'R/W'}]}
....
```

Rationale: diagram titles make generated figures understandable and
referenceable. Meaningful titles can often be derived from nearby caption text,
section context, or the diagram purpose.

Parser ownership: Asciidoctor.js owns the block parsing and title recognition.
AD012 imports Asciidoctor blocks whose style matches a documented Asciidoctor
Diagram style, then checks the Asciidoctor-derived `title` field. `.Title`,
`[title="..."]`, and `title="..."` on the diagram attribute list are accepted
exactly as Asciidoctor parses them.
