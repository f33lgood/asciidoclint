# AD044 - local-adoc-link

Tags: core, links, xref
Severity: warning
Fixability: unsafe.
Fix helper: Change `link:file.adoc#id[text]` to `xref:file.adoc#id[text]` when the target is an AsciiDoc source file and does not use URL query semantics.

Description: Local AsciiDoc files should be referenced with `xref`, not `link`.

Necessity: Asciidoctor documents `link:` for relative non-AsciiDoc files and says relative AsciiDoc files should use `xref:` instead. Using `link:` for an AsciiDoc source file can point rendered output at the source `.adoc` file rather than the converted output file.

Rationale: Local Asciidoctor.js behavior confirms the rendering difference. `link:b.adoc#target[]` renders as `b.adoc#target`; `xref:b.adoc#target[]` renders as the converted target such as `b.html#target`.

Bad:

What's wrong: The target is an AsciiDoc source file, but `link:` emits a literal hyperlink to `chapter.adoc#setup`.

```asciidoc
link:chapter.adoc#setup[Setup]
```

Good:

Expected: `xref:` lets Asciidoctor treat `chapter.adoc` as an AsciiDoc document reference and rewrite it to the converted output target.

```asciidoc
xref:chapter.adoc#setup[Setup]
```

Allowed:

Expected: A query string normally means the author wants URL/link semantics. Local Asciidoctor.js testing shows `xref:b.adoc?rev=1[]` renders to the same `b.adoc?rev=1` target as `link:b.adoc?rev=1[]`, so AD044 does not report this form.

```asciidoc
link:chapter.adoc?rev=1[Source revision]
```

AsciiDoc/Asciidoctor basis: The link macro documentation says `link:` is for relative non-AsciiDoc files and that relative AsciiDoc files should use the xref macro.

Rendering rationale: In HTML output, `link:b.adoc#target[]` stays `b.adoc#target`, while `xref:b.adoc#target[]` becomes `b.html#target`. The difference is output-affecting, so AD044 is a built-in warning rather than a custom style rule.

Implementation note: AD044 is a narrow source scanner. It only reports unescaped
`link:` targets ending in `.adoc`, `.asciidoc`, or `.asc`, with an optional
`#fragment`. It skips protected blocks such as listing, literal, source,
passthrough, stem, diagram, and comment blocks. It does not report external
URLs, query-string links, or non-AsciiDoc local files, which remain AD027
territory.
