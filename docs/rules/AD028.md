# AD028 - image-alt-text

Tags: `accessibility`, `image`
Severity: warning
Fixability: no.
Fix helper: Replace the empty alt attribute with concise text that identifies the image purpose, or remove the explicit empty alt when the derived target name is acceptable.

Necessity: Asciidoctor allows image macros with empty attribute lists and derives fallback alt text from the image target. However, an explicit empty alt attribute renders empty `alt` text, which weakens accessible output and fallback text.

Rationale: The Asciidoctor image documentation says the first positional image attribute is alt text, and the positional-attribute documentation maps `image:` and `image::` position 1 to `alt`. Empty brackets are acceptable because Asciidoctor derives a fallback, but `alt=""`, `alt=" "`, `alt=''`, `[""]`, or `['']` intentionally suppresses useful alternate text.

Images should not explicitly set empty alt text.

Bad:

What's wrong: The block image explicitly sets an empty `alt` attribute. The inline image explicitly sets an empty first positional alt value.

```asciidoc
image::diagram.png[alt=""]

Click image:play.png[""] to start.
```

Good:

Expected: The image macros provide concise alternate text.

```asciidoc
image::diagram.png[Architecture diagram]

Click image:play.png[Play] to start.
```

Allowed:

Expected: Empty brackets are not reported because Asciidoctor derives fallback alt text from the image target.

```asciidoc
image::diagram.png[]

Click image:play.png[] to start.
```

AsciiDoc/Asciidoctor basis: The image documentation describes block and inline image macros, says alt text is entered in the square brackets, and says inline image alt text has the same requirements as block image alt text. The positional attribute documentation maps the first positional attribute of both `image:` and `image::` to `alt`.

Asciidoctor.js behavior: Local rendering confirms `image::diagram.png[]` and `image:play.png[]` produce derived `alt` values from the target names, while `image::diagram.png[alt=""]`, `image::diagram.png[""]`, and `image:play.png[alt=""]` render empty `alt` values.

Parser ownership: AD028 uses the Asciidoctor-derived block image model for block images. Asciidoctor.js does not expose inline image nodes through the current normalized block model, so AD028 uses a narrow source scanner only for inline `image:` macros with explicitly empty alt syntax. The scanner does not report empty brackets, width/height-only forms such as `[,20,20]`, or images inside protected blocks.
