# AD028 - image-alt-text

Tags: `accessibility`, `image`, `docx`
Severity: warning
Fixability: no.
Fix helper: Replace the empty or generated placeholder alt attribute with concise text that identifies the image purpose, or remove the explicit empty alt when the derived target name is acceptable.

Necessity: Asciidoctor allows image macros with empty attribute lists and derives fallback alt text from the image target. However, an explicit empty alt attribute renders empty `alt` text, and imported placeholders ending with `Description automatically generated` carry weak imported descriptions into accessible output.

Rationale: The Asciidoctor image documentation says the first positional image attribute is alt text, and the positional-attribute documentation maps `image:` and `image::` position 1 to `alt`. Empty brackets are acceptable because Asciidoctor derives a fallback, but `alt=""`, `alt=" "`, `alt=''`, `[""]`, or `['']` intentionally suppresses useful alternate text. document authoring tools can also generate placeholder descriptions during DOCX authoring; imported placeholders should be replaced with reviewed author text.

Images should provide meaningful alt text.

Bad:

What's wrong: The first block image explicitly sets an empty `alt` attribute. The second carries imported placeholder description text.

```asciidoc
image::diagram.png[alt=""]

image::chart.png[A screenshot of a chart Description automatically generated]
```

Good:

Expected: The image macros provide concise alternate text.

```asciidoc
image::diagram.png[Overview diagram]

Click image:play.png[Play] to start.
```

Allowed:

Expected: Empty brackets are not reported because Asciidoctor derives fallback alt text from the image target.

```asciidoc
image::diagram.png[]

Click image:play.png[] to start.
```

AsciiDoc/Asciidoctor basis: The image documentation describes block and inline image macros, says alt text is entered in the square brackets, and says inline image alt text has the same requirements as block image alt text. The positional attribute documentation maps the first positional attribute of both `image:` and `image::` to `alt`.

Asciidoctor.js behavior: Local rendering confirms `image::diagram.png[]` and `image:play.png[]` produce derived `alt` values from the target names, while `image::diagram.png[alt=""]`, `image::diagram.png[""]`, and `image:play.png[alt=""]` render empty `alt` values.

Parser ownership: AD028 uses the Asciidoctor-derived block image model for block images. Asciidoctor.js does not expose inline image nodes through the current normalized block model, so AD028 uses a narrow source scanner for inline `image:` macros with explicitly empty alt syntax and for imported placeholder descriptions in image macro attributes. The scanner does not report empty brackets, width/height-only forms such as `[,20,20]`, or images inside protected blocks.

External evidence: Microsoft documents automatic alt text generation in
Microsoft 365 and recommends reviewing/removing generated comments rather than
publishing them verbatim:
https://support.microsoft.com/en-us/accessibility/office-accessibility/everything-you-need-to-know-to-write-effective-alt-text
