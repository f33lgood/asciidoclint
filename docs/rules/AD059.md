# AD059 - docx-nested-table-structure

Tags: `cleanup`, `conversion`, `docx`, `pandoc`, `table`
Severity: warning
Fixability: no.
Fix helper: Convert same-separator nested tables to alternate separators, or flatten deeply nested tables.

Necessity: DOCX-to-AsciiDoc conversion can leave nested table source that does
not match Asciidoctor's nested table syntax. If an inner table uses the same
separator as the containing table, Asciidoctor treats the inner delimiter as the
outer table boundary. Deep table nesting is also fragile in Asciidoctor.js
output and is difficult to maintain.


DOCX-converted nested tables should use valid nested table separators and
shallow nesting.


Bad:

```asciidoc
[cols="1,1"]
|===
|Outer a|
[cols="1,1"]
|===
|Nested |Broken
|===
|===
```

What's wrong: The nested table uses the same `|===` delimiter as the containing
table, so the inner delimiter closes the outer table instead of starting a
nested table.

Good:

```asciidoc
[cols="1,1"]
|===
|Outer a|
[cols="1,1"]
!===
!Nested !Valid
!===
|===
```

Expected: The nested table uses `!===` and `!` cell markers, so Asciidoctor can
distinguish it from the containing `|===` table.

Rationale: Current Pandoc can emit `!===` for one level of DOCX nested tables,
but older converted documents and post-processed output may still contain
same-separator nested tables. Tables nested deeper than three total table levels
are risky in Asciidoctor.js and should be reviewed instead of accepted silently.

AsciiDoc/Asciidoctor basis: Asciidoctor documents nested tables in `a` table
cells and says the nested table must use a table delimiter and cell separator
that differ from the enclosing table.

Parser ownership: AD059 is a source scanner because Asciidoctor may parse the
broken same-separator delimiter as a normal table close and may not emit a
diagnostic. The source pattern is the evidence of the conversion residue.

Implementation note: AD059 reports a `[cols...]` or titled nested table opening
that uses the same delimiter marker as the currently open table after an
AsciiDoc-style table cell has appeared. It also warns when source table nesting
exceeds three total table levels.
