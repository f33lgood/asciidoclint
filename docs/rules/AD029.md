# AD029 - markdown-link-image-residue

Tags: `conversion`, `link`, `image`
Severity: warning
Fixability: unsafe.
Fix helper: Rewrite the residue using the intended AsciiDoc macro: `link:target[text]`, `xref:target[text]`, or `image::target[Alt text]`.

Necessity: Markdown link and image syntax such as `[text](target)` and
`![alt](image.png)` renders as paragraph text in Asciidoctor, so the intended
link or image is lost.

Markdown link and image residue should not render as text.

Bad:

```asciidoc
See [Architecture](architecture.adoc).

![Diagram](diagram.png)

(https://example.com)[Example]
```

Good:

```asciidoc
See xref:architecture.adoc[Architecture].

image::diagram.png[Diagram]

link:https://example.com[Example]
```

AsciiDoc/Asciidoctor basis: Asciidoctor documents Markdown-compatible syntax as
an optional AsciiDoc feature. The documented compatible forms include
Markdown-style headings, fenced code blocks, blockquotes, and thematic breaks.

Asciidoctor.js behavior: Markdown link and image forms such as `[text](target)`
and `![alt](image.png)` render as paragraph text, not as links or images. A
reversed link form such as `(https://example.com)[Example]` renders as malformed
link-like text rather than the intended link label and target.

Parser ownership: AD029 is a narrow source scanner because Asciidoctor preserves
these residues as ordinary paragraph text and does not emit diagnostics for the
lost intent. It intentionally does not parse or reject all Markdown-looking
syntax.

Implementation note: AD029 does not report Markdown-compatible headings,
fenced code blocks, blockquotes, or thematic breaks. It also skips protected
blocks such as source, listing, literal, passthrough, diagram, stem, and comment
blocks.

Fixability note: AD029 offers unsafe fixes for the narrow residue forms it
matches. The fix changes Markdown syntax to `link:`, `xref:`, `image:`, or
`image::` based on target shape and whether the image residue is alone on the
line. The fix is unsafe because choosing link versus xref semantics and inline
versus block image semantics can require author intent.
