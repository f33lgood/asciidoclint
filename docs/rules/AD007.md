# AD007 - heading-depth-limit

Tags: `core`, `headings`
Severity: error
Fixability: no.
Fix helper: Reduce the heading marker to six or fewer `=` / `#` characters, or split the content into a separate document if the hierarchy is too deep.

Necessity: Asciidoctor supports a finite section depth. Deeper heading markers are not reliable section structure and may render as ordinary text or malformed headings depending on backend behavior.


Section headings should not exceed Asciidoctor's supported depth.

Bad:

```asciidoc
= Title

======= Too Deep
```

What's wrong: Asciidoctor does not recognize seven `=` markers as a section
title. The line renders as paragraph text and is absent from the document
outline. Asciidoctor does not emit a native diagnostic for this case.

Good:

```asciidoc
= Title

== Parent

=== Child

==== Level 3

===== Level 4

====== Deepest Supported
```

Expected: The deepest supported section level uses six `=` markers, which
Asciidoctor maps to section level 5 and renders as an HTML `<h6>`.

Rationale: Asciidoctor documentation says the section marker can range from two
to six equals signs for section levels 1 through 5, with one equals sign used for
the document title / level 0. Asciidoctor also recognizes Markdown-style `#`
section markers through six markers. Seven or more markers are not section
syntax.

Implementation note: AD007 is a source-text rule outside protected blocks because
Asciidoctor does not create section nodes or diagnostics for unsupported
heading-like marker runs. It complements AD001, which checks skipped levels among
sections Asciidoctor does recognize.

Parser ownership: AD007 must source-scan because unsupported heading marker
runs are parsed as paragraph text and disappear from the Asciidoctor section
model. The scanner intentionally covers the two section marker families
documented by Asciidoctor, `=` and Markdown-compatible `#`, and only reports
seven or more markers outside protected blocks.
