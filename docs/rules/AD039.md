# AD039 - punctuation-passthrough-residue

Tags: cleanup, conversion
Severity: warning
Fixability: safe.
Fix helper: Replace the passthrough-wrapped punctuation with the literal
character when AD039 reports it.

Necessity: Inline passthroughs are valid AsciiDoc. Asciidoctor documents them
as a way to prevent or control substitutions, including escaping characters
that otherwise have special meaning. AD039 therefore does not ban passthroughs;
it only reports a small allowlist of conversion-residue forms where replacing
the wrapper preserves rendered output in normal source text: `++_++`, `++[++`,
`++]++`, `++<++`, `++>++`, and `++|++`.

Parser ownership: Asciidoctor.js is the behavior baseline and does not emit a
diagnostic for this residue. AD039 uses a narrow source scanner for the explicit
allowlist above. It skips protected blocks, skips `++|++` in table bodies, and
does not report standalone bracket-pass lines such as `++[++source++]++` because
removing the wrappers could turn the line into block metadata. It preserves
other valid passthrough forms such as `all-natural++*++`, `dev++{conf}++`,
passthrough link targets, triple-plus HTML, and passthrough blocks.

Inline passthrough wrappers around safe punctuation should be removed when they
appear as conversion residue.

Bad:

```adoc
DEVICE++_++STATUS and PORT++[++0-3++]++
```

What's wrong: Asciidoctor renders this as `DEVICE_STATUS and PORT[0-3]`, but
the source still carries conversion residue.

Good:

```adoc
DEVICE_STATUS and PORT[0-3]
```

Expected: The literal punctuation remains, and the unnecessary passthrough
wrappers are gone.

Allowed:

```adoc
all-natural++*++ text
dev++{conf}++
link:++https://example.org/now_this__link_works.html++[]
+++
<custom-output/>
+++
```

Rendering rationale: the reported allowlist renders as the same literal
punctuation after the wrapper is removed. `++*++` and brace passthroughs are not
reported because removing them can create emphasis or attribute substitution in
some contexts.
