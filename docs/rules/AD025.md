# AD025 - missing-image

Tags: `dependencies`, `image`
Severity: error
Fixability: no.
Fix helper: Create the image file, fix the image target or imagesdir value, or use a URL target when the image is intentionally remote.

Necessity: A missing image target renders as a broken image or omitted visual artifact. The visible document is incomplete.

Description: Image targets should exist after attribute substitution.

Rationale: HTML output can still contain an `<img>` element for a missing local image, but the delivered document is incomplete. Converters that embed images, such as PDF or data-uri workflows, need the target to be resolvable at conversion time.

Bad:

What's wrong: `missing.png` is a local image target, but the file is not present after applying `imagesdir`.

```asciidoc
image::missing.png[]
```

Good:

Expected: The local image target exists.

```asciidoc
image::diagram.png[Overview diagram]
```

Also good:

Expected: `imagesdir` points to the image catalog, and the image macro names the target relative to that catalog.

```asciidoc
:imagesdir: images
image::diagram.png[Overview diagram]
```

Also good:

Expected: Inline image macros are checked the same way as block image macros.

```asciidoc
See image:icon.svg[Status icon].
```

Also good:

Expected: Remote image targets are intentionally external and are not checked as local files.

```asciidoc
image::https://example.com/diagram.png[Remote diagram]
```

AsciiDoc/Asciidoctor basis: Asciidoctor documents both block and inline image
macros. It documents `imagesdir` as the image catalog prefix for relative image
targets and says URL targets ignore `imagesdir`. It also notes that image
targets must be resolvable at conversion time when the converter embeds the
image.

Implementation note: AD025 uses the normalized dependency graph. The graph
checks local block and inline image targets after attribute substitution and
`imagesdir` resolution. URL image targets and URL `imagesdir` catalogs are
treated as external and skipped by this local-file rule.
