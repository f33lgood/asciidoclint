# AD055 - docx-anchor-caption-residue

Tags: cleanup, conversion, docx
Severity: warning
Fixability: no.
Fix helper: Replace the generated bookmark with a semantic anchor and
convert the caption text to a meaningful `.Title` line immediately before the
corresponding figure or table.

Necessity: DOCX-to-AsciiDoc conversion can leave bookmark IDs and caption
text in one source line, such as
`[#_Toc142906677 .anchor]####Figure 3-1. Overview details` or
`[#_Ref142906678 .anchor]####Table 1: Feature list`. Asciidoctor
renders that line as visible paragraph text instead of attaching it to a figure
or table.

DOCX anchor caption residue should be converted to AsciiDoc titles.

Bad:

```adoc
[#_Toc142906677 .anchor]####Figure 3-1. Overview details
```

What's wrong: `_Toc...` / `_Ref...` bookmarks are generated bookmark identifiers,
`.anchor` is imported role/class residue, and `####Figure...` is rendered as
paragraph text rather than an AsciiDoc title.

Good:

```adoc
[#fig-overview-details]
.Overview details
image::overview.png[Overview details]
```

Expected: The source uses a semantic anchor and an AsciiDoc block title. The
generated figure or table number is left to Asciidoctor.

Repair guidance: Use a semantic anchor such as `[#fig-meaningful-id]` or
`[#table-meaningful-id]` only when it is placed immediately before the matching
image or table block. Preserve the meaningful caption text and do not invent
placeholder titles.

Rendering rationale: Asciidoctor treats the residue line as paragraph text. The
caption is detached from the figure/table semantics, and generated HTML can show
literal `#Figure` or `#Table` text to readers.

Implementation note: AD055 intentionally matches a narrow DOCX/Pandoc residue
fingerprint: a generated `_Toc`, `_Ref`, or `_Hlk` ID, the `.anchor` role,
two or more hash characters, and a `Figure` or `Table` caption on the same
line. It accepts common DOCX caption number separators such as `.`, `:`, and
imported dash variants. It skips protected blocks. This keeps false positives low and leaves
broader conversion cleanup to custom rules or author review.

External evidence: The Asciidoctor MS Word migration guide recommends Pandoc
for DOCX-to-AsciiDoc conversion, then explicitly calls for tidying the output,
deleting automatic IDs, and turning caption paragraphs back into Asciidoctor
captions:
https://docs.asciidoctor.org/asciidoctor/latest/migrate/ms-word/
