# AD010 - table-title

Tags: `core`, `table`
Severity: warning
Fixability: no.
Fix helper: Add a meaningful table title using `.Title` above the table metadata, or set `title="..."` in a table attribute list. Do not use generic placeholders such as `.Table Table`.

Necessity: A table without a block title renders, but generated captions, figure/table lists, and nearby xrefs have no human-readable title to show. A generic placeholder title such as `.Table Table` has the same practical problem because it does not identify the table.


Table blocks should have a title. Asciidoctor table titles are optional, but
when present they render as numbered captions such as `Table 1. Register
fields`.

Bad:

```asciidoc
|===
| A | B
|===
```

Also bad:

```asciidoc
.Table Table
|===
| A | B
|===
```

Good:

```asciidoc
.Register fields
|===
| A | B
|===
```

Also good:

```asciidoc
[title="Register fields"]
|===
| A | B
|===
```

Rationale: table titles make rendered tables referenceable and easier to review. Meaningful titles can often be derived from nearby section text, table header labels, an imported caption, or the table purpose.

Parser ownership: Asciidoctor owns table recognition and table title parsing.
AD010 checks normalized Asciidoctor table blocks and accepts both block title
syntax and `title="..."` table metadata.
