# AD045 - markdown-heading-mix

Tags: headings, markdown-compatibility, maintainability
Severity: info
Fixability: unsafe.
Fix helper: Convert the less common heading marker style to the dominant style in the document graph, preserving the marker length.

Description: Markdown-compatible headings should not be mixed with AsciiDoc headings.

Necessity: Asciidoctor accepts Markdown-style headings as optional compatibility syntax. Mixing `=` and `#` heading marker styles in one document graph is not invalid, but it makes hierarchy review and source maintenance harder.

Rationale: AsciiDoc documents are often split across included files. A single rendered document that mixes heading marker families forces authors to mentally normalize two heading systems while reviewing section depth.

Bad:

What's wrong: The document graph uses both AsciiDoc `=` headings and Markdown-compatible `#` headings.

```asciidoc
= Title

== Overview

## Markdown-style Section
```

Good:

Expected: Use one heading marker style consistently.

```asciidoc
= Title

== Overview

== AsciiDoc-style Section
```

Also good:

Expected: A document graph may consistently use Markdown-compatible heading syntax because Asciidoctor supports it.

```asciidoc
## Overview

## Markdown-style Section
```

AsciiDoc/Asciidoctor basis: Asciidoctor documents Markdown-style headings as Markdown-compatible syntax. This rule therefore does not reject Markdown-style headings by themselves.

Asciidoctor.js behavior: Asciidoctor parses both `=` and `#` heading markers as
section structure. `# Title` can be a document title, and `## Section` maps to
the same section level as `== Section`. Asciidoctor can report ordinary
section-level errors, but it does not report mixed heading marker style.

Parser ownership: AD045 uses a source scanner to read the heading marker family
from lines that Asciidoctor-style section parsing accepts. The normalized
section model identifies section structure, but the source line is needed to
know whether the marker was `=` or `#`. The scanner intentionally covers
Asciidoctor's supported single-line marker families and ignores historical
setext forms.

Implementation note: AD045 scans the full parsed document graph, including included files. It skips headings inside protected blocks such as source, listing, literal, passthrough, diagram, stem, and comment blocks. When both styles are present, it reports headings that use the less common style and offers an unsafe marker replacement.
