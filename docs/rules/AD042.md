# AD042 - interdocument-xref-text

Tags: xref, links, accessibility
Severity: warning
Fixability: no.
Fix helper: Add human-readable text as the first xref attribute, before named attributes such as window or xrefstyle.

Necessity: Asciidoctor documents link text for interdocument xrefs as currently
required. When it is omitted, Asciidoctor.js still renders a link, but the
visible label falls back to the converted output filename instead of meaningful
reader-facing text.

Rationale: Intradocument xrefs such as `xref:overview[]` and `<<overview,>>`
can derive text from the referenced target, so they are not violations.
External URL macros and `link:` macros can also derive fallback labels from the
target. This rule is limited to interdocument `xref:` macros whose target is an
AsciiDoc source file.

Bad:

What's wrong: the xref points to another AsciiDoc file but omits explicit link
text, so the rendered label falls back to the output file name.

```asciidoc
See xref:chapter.adoc[].
See xref:chapter.adoc#overview[window=_blank].
```

Good:

Expected: the first positional xref attribute provides text for readers, and
named attributes come after it.

```asciidoc
See xref:chapter.adoc[Chapter overview].
See xref:chapter.adoc#overview[Overview,window=_blank].
```

Implementation note: This rule source-scans inline `xref:` macros because the
missing source text is not preserved as a distinct Asciidoctor diagnostic. It
only treats `.adoc` and `.asciidoc` targets as interdocument xrefs, and it skips
escaped macros and protected blocks.
