# AD032 - blank-before-block

Tags: `cleanup`, `blocks`
Severity: error when the missing blank line can change Asciidoctor parsing; warning otherwise
Fixability: safe.
Fix helper: Insert one blank line before the block delimiter. This is the safe automatic fix emitted by asciidoclint.

Necessity: Asciidoctor is the language baseline until the AsciiDoc Language Specification is ratified. A delimiter immediately after paragraph text can be parsed as a section underline instead of the intended delimited block boundary for delimiter lines such as `====`, `----`, and `++++`. Other delimited blocks are still expected to be separated from preceding text by Asciidoctor's documented block structure and recommended practices.


Structural block delimiters should be preceded by a blank line.


Bad:

```asciidoc
Text
====
example
====
```

What's wrong: Asciidoctor can parse `Text` plus `====` as a section title
instead of paragraph text followed by an example block. That changes the
document structure and can also leave the intended block unterminated.

Good:

```asciidoc
Text

====
example
====
```

Expected: The blank line makes the block boundary explicit, so Asciidoctor
parses the preceding text as a paragraph and the delimiter as the start of the
intended block.

Rationale: Missing separation before a delimited block is sometimes a rendering
correctness issue and otherwise violates the documented, recommended shape of a
delimited block.

AsciiDoc/Asciidoctor basis: Asciidoctor documents delimited blocks as linewise
structural containers with matching opening and closing delimiters. The basic
block guide shows entering the opening delimiter after the preceding text is
separated by a blank line.

Asciidoctor.js behavior: Local rendering confirms that missing separation before
`====`, `----`, and `++++` can make Asciidoctor parse the preceding line and
delimiter as section syntax instead of a delimited block. Other delimiter
families, such as `****`, `____`, `....`, `--`, and table delimiters, usually
still render as blocks, so they remain warnings.

Parser ownership: AD032 uses a source scanner because it needs to detect the
author's missing separator before parsing has already chosen a block or section
interpretation. The scanner recognizes the documented structural delimiter
families, including longer matching delimiter lines and table delimiter variants
such as `|===`, `,===`, `:===`, and `!===`.

Implementation note: AD032 skips closing delimiters, protected block content,
block metadata directly above a delimiter, section titles, anchors, and list
continuation markers. The safe fix inserts a single blank line before the
opening delimiter.
