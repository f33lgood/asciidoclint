# Rule Necessity and Severity Rationale

Date: 2026-05-28

This report argues why each built-in `asciidoclint` rule exists. A rule is not
included merely because another linter has a similar check. The rule must be
justified by one of these facts:

- the structure can break or materially change AsciiDoc rendering;
- the structure can hide missing rendered content or unresolved references;
- the structure renders visibly but fails a baseline requirement for a
  well-structured technical document.

Severity is assigned from rendering impact:

- **error**: the source is syntactically broken, a referenced local artifact is
  missing, or the intended rendered content cannot be trusted.
- **warning**: AsciiDoc usually renders a visible document, but the structure is
  ambiguous, misleading, unstable, or likely to produce the wrong visible
  result.
- **info**: the source renders, but the rule records a documentation-quality or
  portability expectation that teams commonly want to review.

## Rule Matrix

| Rule | Primary severity | Fixability | Parser ownership | Necessity argument |
|---|---|---|---|---|
| `AD000/asciidoctor-diagnostic` | mirrors Asciidoctor | no | Asciidoctor.js diagnostic | Asciidoctor diagnostics are reference parser/render findings. They should appear as structured lint findings with source locations instead of requiring users to inspect renderer stderr separately. |
| `AD001/heading-level-progression` | error | no | Asciidoctor.js diagnostic | Asciidoctor documentation says nested section levels must be sequential, levels cannot be skipped, and skipped nesting is illegal. Asciidoctor renders the document with a native warning, but the generated section tree jumps over a parent level and the outline is not trustworthy for TOCs, navigation, and readers using section hierarchy. |
| `AD002/single-document-title` | error | no | Asciidoctor.js diagnostic | Asciidoctor documentation says a document can only have multiple level-0 sections when `doctype` is `book`; otherwise, an additional level-0 section violates the section-level rules. Asciidoctor reports this as an error in article documents. |
| `AD003/unterminated-block` | error | no | Asciidoctor.js diagnostic | Asciidoctor reports unterminated delimited blocks as native parser diagnostics. An unclosed delimiter changes rendering for every following line until EOF or another delimiter, so AD003 wraps the native diagnostic with a stable documented rule ID instead of duplicating parser logic in the tolerant scanner. |
| `AD004/table-cell-count` | warning | no | Asciidoctor.js table model plus bounded source inspection | Asciidoctor accepts table cell streams and derives rows from the cell order, column count, and spans. Cells may be written on the same line or consecutive lines, so source-line row counting is not valid. AD004 uses Asciidoctor table spans and rendered cell counts plus conservative source inspection to catch omitted cells when an incomplete final row leaves source data out of the rendered table. |
| `AD005/explicit-document-title` | info | no | normalized document model with Asciidoctor-compatible section/title scanning | Asciidoctor says the document header and document title are optional for `article` and `book`. It can still infer fallback title metadata from the first section. For publishable technical document roots, an explicit title remains useful for predictable metadata, HTML page titles, and PDF title pages. Accepted explicit forms are a level-0 document title, `:doctitle:`, `:title:`, or a wrapper title include. |
| `AD006/included-document-title` | error | no | normalized include graph and section scanner, checked against Asciidoctor behavior | A level-0 title inside an included file is expanded into the parent document. If the parent article already has a document title, Asciidoctor reports `level 0 sections can only be used when doctype is book`. The documented way to include standalone chapter-like files under an article parent is `leveloffset`. Wrapper documents may intentionally use the first include as the root document title, and `doctype=book` documents may intentionally include level-0 book parts, so the rule allows both cases. |
| `AD007/heading-depth-limit` | error | no | source scanner | Asciidoctor documentation limits section levels to 0 through 5. Seven or more `=` or `#` markers are not recognized as section titles, render as paragraph text, and do not appear in the document outline. Asciidoctor does not emit a native diagnostic, so AD007 is a source-text rule outside protected blocks. |
| `AD008/blank-before-list` | warning | safe | source scanner | Asciidoctor documents that lists need empty lines to separate them from other blocks. Without the blank line after paragraph text, the would-be list marker is rendered as paragraph text and the intended list block is not created. |
| `AD010/table-title` | warning | no | Asciidoctor.js table model | Asciidoctor says table titles are optional, but a titled table renders with a numbered caption and gives xrefs/lists/reviews a human-readable table identity. AD010 uses Asciidoctor table blocks and accepts `.Title` and `title="..."` metadata. |
| `AD011/image-title` | warning | no | Asciidoctor.js image block model | Asciidoctor says image titles are optional, but a titled block image renders as a numbered figure caption. Without one, readers only get surrounding prose or alt text, which serves a different accessibility purpose. AD011 checks Asciidoctor-derived image blocks, so `.Title`, `[title="..."]`, and the block image macro `title` attribute are accepted as Asciidoctor parses them. |
| `AD012/diagram-title` | warning | no | Asciidoctor.js block model plus documented diagram style set | Diagram blocks are extension-backed figures. They render without titles, but long technical documents need stable diagram captions for review and cross-reference context. AD012 checks Asciidoctor-derived blocks whose style matches documented Asciidoctor Diagram styles, then uses the Asciidoctor-derived `title` field. |
| `AD013/standalone-inline-image` | warning | unsafe | source scanner for standalone inline image macro spelling | `image:target[]` is inline syntax. A line containing only an inline image renders as a paragraph with an inline image span, not as an Asciidoctor image block. Asciidoctor exposes the paragraph but not a normalized inline-image node, so AD013 uses a narrow source scanner. The fix is unsafe because changing `image:` to `image::` intentionally changes rendered block semantics. |
| `AD016/malformed-figure-caption` | warning | no | Asciidoctor.js image/diagram block model plus immediate adjacent-line source scan for imported caption residue | A plain `Figure 1:` line directly adjacent to an image or diagram renders as a paragraph, not as the figure title. The visible caption is separated from the figure semantics. The rule intentionally does not search across blank lines or intervening elements, except the required diagram style line such as `[plantuml]`. |
| `AD017/malformed-table-caption` | warning | no | Asciidoctor.js table block model plus immediate adjacent-line source scan for imported caption residue | A plain `Table 1:` line directly adjacent to a table renders as a paragraph, not as the table title. The visible caption is separated from the table semantics. The rule intentionally does not search across blank lines or intervening elements. |
| `AD019/content-after-include` | warning | no | source scanner and include graph | Asciidoctor recommends empty lines around include directives. Include expansion happens before rendering, so nonblank parent content after a whole-file include can visually attach to the included content or stop a following section title from becoming a section when the included file does not provide a trailing blank line. |
| `AD020/appendix-section-level` | warning | no | source scanner checked against doctype and Asciidoctor level-0 diagnostics | Asciidoctor documents article appendices as level-1 sections and reports `[appendix]` followed by `=` in an article as a level-0 section error. The same level-0 appendix is valid in multipart books, so book documents are exempt. |
| `AD022/circular-include` | error | no | normalized include graph | Asciidoctor processes includes recursively and only stops cycles when its include-depth safeguard is exceeded, which produces a depth-limit diagnostic rather than the actual cycle. AD022 reports the circular include relationship directly using the resolved include graph. |
| `AD023/empty-section` | info | no | normalized section model | Asciidoctor allows empty sections and auto-generates section IDs by default. A visible heading with no body content or child section is not invalid, but it is usually unfinished authoring structure or conversion/bookmark residue and creates an empty outline node. |
| `AD024/missing-include` | error | no | normalized dependency graph | Asciidoctor reports missing required includes and inserts an unresolved directive into output. AD024 reports the dependency failure after attribute substitution while skipping optional and external includes. |
| `AD025/missing-image` | error | no | normalized dependency graph | Missing local image targets produce incomplete publishable output; embedding converters need the asset at conversion time. AD025 checks local block and inline images after `imagesdir` resolution while skipping remote URL targets. |
| `AD026/missing-xref` | error | no | source scanner for xref occurrences; Asciidoctor.js catalog refs for same-document targets; dependency graph for file targets | A missing `xref:target[]` or shorthand `<<target>>` target renders as an unresolved reference or broken link. Readers cannot navigate to the intended section, table, figure, or file. |
| `AD027/missing-local-link` | error | no | normalized dependency graph | Asciidoctor renders relative `link:` targets without checking that the local file exists. AD027 catches broken local non-AsciiDoc file links after attribute substitution while leaving `xref:` to AD026 and URL/mail links to external-link policy. |
| `AD028/image-alt-text` | warning | no | Asciidoctor.js block image model; narrow source scanner for inline image macros with explicitly empty alt syntax | Asciidoctor derives fallback alt text from the image target for empty brackets, but explicit empty alt syntax renders an empty `alt` value. AD028 reports explicit empty alt text for block and inline images while allowing derived fallback alt text. |
| `AD029/markdown-link-image-residue` | warning | unsafe | source scanner for residue Asciidoctor leaves as text | Markdown link and image syntax such as `[text](target)` and `![alt](image.png)` renders as paragraph text in Asciidoctor, so the intended link or image is lost. The unsafe fix rewrites the narrow matched form to an AsciiDoc link, xref, inline image, or block image macro, but author intent can affect the best macro. |
| `AD030/markdown-table-residue` | warning | no | source scanner for residue Asciidoctor leaves as text | Markdown pipe table separator lines render as paragraph text in AsciiDoc, not as a table delimiter. The intended table is lost. AD030 skips real AsciiDoc table blocks because dash rows can be ordinary cell content there. |
| `AD031/no-nested-link-text` | warning | no | source scanner for link, xref, and URL macro visible text | Nested link macros or cross references inside visible link text can render invalid nested anchors, malformed labels, or escaped reference text. AD031 catches this conversion residue while skipping protected blocks. |
| `AD032/blank-before-block` | error or warning | safe | source scanner for documented delimiter families, checked against Asciidoctor behavior | Missing separation before `====`, `----`, or `++++` can make Asciidoctor parse preceding text as a section title instead of parsing the intended delimited block. Other missing blank lines before block delimiters violate Asciidoctor's documented block shape and remain warnings. |
| `AD034/no-hard-tabs` | warning | safe | source scanner for ordinary source lines, excluding protected blocks and table bodies | Asciidoctor accepts tabs, but hard tabs in prose and structural markup render with environment-dependent widths. Tabs can be intentional data in verbatim content and TSV tables, so AD034 skips those contexts and only applies the safe cleanup where a tab can be replaced by a space without changing AsciiDoc structure. |
| `AD035/blank-after-block` | warning | safe | source scanner for documented delimiter families, checked against Asciidoctor recommendations | Asciidoctor can render following text correctly, so this is not an error. A blank line after a closing delimiter follows Asciidoctor's documented paragraph/block separation shape and makes the source boundary explicit. |
| `AD036/list-marker-residue` | warning | no | source scanner for marker-only unordered and ordered list residue, excluding block delimiters, protected blocks, and table bodies | Asciidoctor requires principal text after a list marker. Marker-only lines such as `*`, `**`, `-`, `.`, `..`, and `10.` render as visible paragraph residue or nearby paragraph content, not as valid empty list items. |
| `AD037/underline-residue` | warning | no | source scanner for exactly `___`, excluding protected blocks and table bodies | Asciidoctor uses four or more underscores as quote block delimiters, but exactly three underscores are not section, thematic-break, or quote-block syntax. They render as visible residue, often from converted underline styling. |
| `AD039/punctuation-passthrough-residue` | warning | safe | source scanner for `++_++`, `++[++`, `++]++`, `++<++`, `++>++`, and `++\|++`; protected blocks are skipped and table-body `++\|++` is skipped | Inline passthroughs are valid AsciiDoc, but these punctuation wrappers are frequent conversion residue. Replacing them with literal punctuation preserves rendered output in ordinary source text while keeping riskier passthroughs such as `++*++` and `++{name}++` untouched. |
| `AD040/html-link-text-residue` | warning | no | source scanner for raw HTML/XML-looking fragments in `link:` and `xref:` labels, excluding comments and protected blocks | Raw tag-like fragments inside link labels are escaped by Asciidoctor and become visible label text. This is usually conversion residue, but the intended human-readable label needs author judgment. |
| `AD041/no-space-in-inline-formatting` | warning | no | source scanner for constrained single `*`/`_` spans and literal monospace `` `+...+` `` spans, excluding comments, protected blocks, table bodies, macro bodies, mixed-formatting spans, and formula-looking text | Asciidoctor documents that constrained formatting pairs cannot contain spaces directly inside the markers. Such spaces can leave the intended markup visible instead of formatting the text. Valid unconstrained pairs such as `** important **` and `__ important __` are allowed. |
| `AD042/interdocument-xref-text` | warning | no | source scanner for interdocument xref macros | Asciidoctor documents interdocument xref link text as currently required. Asciidoctor.js renders omitted text with a weak converted filename fallback, while intradocument xrefs and URL/link macros have documented fallback text behavior and are not violations. |
| `AD043/section-title-start-left` | warning | no | source scanner for indented equal-sign and hash section-title markers | Asciidoctor treats indented section-title-looking lines as literal content, not as sections. This is valid AsciiDoc and can be intentional example text, so the rule is a warning. It catches likely lost section structure that would disappear from the outline, table of contents, and generated IDs. |
| `AD044/local-adoc-link` | warning | unsafe | source scanner for unescaped local link macro targets, excluding protected blocks | Asciidoctor documents `link:` for relative non-AsciiDoc files and `xref:` for relative AsciiDoc files. `link:chapter.adoc[]` renders a literal source-file link, while `xref:chapter.adoc[]` is rewritten to the converted output target. |
| `AD045/markdown-heading-mix` | info | unsafe | source scanner for heading marker style, checked against Asciidoctor-supported heading parsing | Asciidoctor supports Markdown-compatible `#` headings, so using them is valid. Mixing `#` and `=` heading marker families in one document graph is a maintainability issue because authors must normalize two source heading systems while reviewing one rendered hierarchy. |

## Reference Tool Role

Reference tools remain useful for discovering candidate checks and fixtures.
They are not accepted as final justification for a built-in rule.
Each rule above is kept only because it affects rendered AsciiDoc output,
rendered navigation/reference integrity, or a baseline documentation-quality
contract.
