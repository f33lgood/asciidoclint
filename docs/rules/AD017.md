# AD017 - malformed-table-caption

Tags: core, table, docx
Severity: warning
Fixability: no.
Fix helper: Move the caption immediately before the table and convert it to a meaningful `.Title` line without the generated Table number. Preserve or derive the real caption text; do not use placeholders such as `.Table Table`.

Necessity: A plain `Table 1:` or placeholder `Table -:` line adjacent to a table renders as a paragraph, not as the table title. The visible caption is separated from the table semantics.


Table captions should use AsciiDoc title syntax before the table.

Bad:

```adoc
Table 1: Registers
|===
| Name | Value
|===
```

What's wrong: `Table 1: Registers` is paragraph text. It is not attached to the
table as an AsciiDoc title. The same problem applies when the plain caption is
immediately after the table.

Good:

```adoc
.Registers
|===
| Name | Value
|===
```

Expected: The title is a `.Title` line before the table. Do not include the
generated `Table 1.` prefix in the title text; Asciidoctor adds the table number
when rendering titled tables.

Rendering rationale: a plain `Table 1:` line renders as a paragraph, not as the
table title, so the visible caption is detached from the table semantics.

Implementation note: AD017 uses the Asciidoctor-derived table block model for
table positions, then source-scans only the immediately adjacent lines for
imported `Table N:` and `Table -:` caption residue, including multi-part
numbers and imported dash variants. This source scan is necessary because
Asciidoctor correctly parses the residue as an ordinary paragraph, not as failed
title syntax.

Limitation: AD017 intentionally does not search across blank lines, prose,
anchors, attributes, or other elements to find a nearby `Table N:` paragraph. It
catches only the common conversion residue where the plain caption is directly
before the table delimiter or directly after the table block.
