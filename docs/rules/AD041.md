# AD041 - no-space-in-inline-formatting

Tags: cleanup, format, inline
Severity: warning
Fixability: no.
Fix helper: Move spaces outside constrained formatting markers, or use the
correct unconstrained pair when spaces must remain inside the formatted span.

Necessity: AsciiDoc inline formatting is delimiter-sensitive. Asciidoctor
documents that constrained formatting pairs such as `*text*`, `_text_`, and
`` `text` `` cannot contain spaces directly inside the markers. If spaces are
inside single constrained markers, the intended emphasis, strong, or monospace
span may render as literal punctuation instead of formatted text.

Parser ownership: Asciidoctor.js is the behavior baseline and does not emit a
diagnostic for malformed inline formatting. AD041 uses a conservative source
scanner for constrained single `*` and `_` spans with inner spaces, plus literal
monospace spans such as `` `+ code +` ``. It skips line comments, comment
paragraphs, protected blocks, table bodies, inline macro bodies, existing
rendered mixed-formatting spans, and formula-looking text.

Inline formatting markers should not contain inner spaces when constrained
syntax is being used.

Bad:

```asciidoc
This is * important * text and `+ code +` should be fixed.
```

What's wrong: The constrained strong marker and literal monospace wrapper contain
spaces just inside the formatting marks, so the intended formatting can be lost
or the visible text can include unwanted wrapper characters.

Good:

```asciidoc
This is *important* text and `+code+` should be fixed.
```

Expected: The spaces are outside the constrained formatting marks.

Allowed:

```asciidoc
This is ** important ** text.
This is __ important __ text.
```

These unconstrained pairs are valid AsciiDoc when spaces must remain inside the
formatted span. AD041 does not report them.

Rendering rationale: constrained inline formatting requires the formatted text
not to start or end with a space-like character. When a space is needed inside
the formatted text, the author should intentionally use an unconstrained pair
instead of accidentally writing a malformed constrained pair.
