# AD013 - standalone-inline-image

Tags: core, image
Severity: warning
Fixability: unsafe.
Fix helper: Use `image::target[alt]` for standalone figures, and reserve `image:target[alt]` for inline images inside text.

Necessity: `image:target[]` is inline syntax. A line containing only an inline
image renders as a paragraph containing an inline image span, not as an
AsciiDoc image block. That means block image behavior such as figure captions,
block spacing, and block-image rules does not apply.


Standalone image lines should use block image syntax when the author intends a
figure/block image.

Bad:

```adoc
image:diagram.png[Architecture]
```

Good:

```adoc
image::diagram.png[Architecture]
```

Also good:

```adoc
Click image:diagram.png[Architecture] to open the diagram.
```

Expected: Inline image syntax is valid when the image is embedded in paragraph
text. AD013 does not report this form because the line has text before or after
the `image:` macro.

Also good:

```adoc
image:linux.png[Linux,150,150,float="right"]
You can find Linux everywhere these days.
```

Expected: Asciidoctor documents floated inline images for paragraph text flow.
This is still inline image syntax, and the source line contains only the image
macro, so AD013 reports it as a warning. The finding should be reviewed, not
blindly fixed, because the author may intentionally want floated inline image
behavior rather than block figure behavior.

Rendering rationale: Asciidoctor renders a standalone inline image as:

```html
<div class="paragraph">
  <p><span class="image"><img ...></span></p>
</div>
```

By contrast, block image syntax renders as:

```html
<div class="imageblock">...</div>
```

The unsafe fix inserts the second colon, changing `image:` to `image::`. This
intentionally changes paragraph-inline semantics into block-image semantics.
Use it when the image is intended to be a standalone figure.

Parser ownership: Asciidoctor parses a standalone inline image as a paragraph
containing an inline image, not as an image block. It exposes the paragraph
source line but not a normalized inline-image node, so AD013 uses a narrow source
scanner for lines that consist only of `image:target[...]`. Indented lines are
not reported because Asciidoctor parses them as literal content, not as inline
image paragraphs.
