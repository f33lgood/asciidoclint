# AD003 - unterminated-block

Tags: `core`, `blocks`
Severity: error
Fixability: no.
Fix helper: Add the missing closing delimiter that matches the opener. The correct location depends on where the block content should end, so asciidoclint does not insert it automatically.

Necessity: Asciidoctor reports unterminated delimited blocks as native parser diagnostics. An unclosed delimiter changes rendering for every following line until EOF or another delimiter. Content that should render as sections, paragraphs, lists, or tables can become one large listing/example/table block.


Delimited blocks should have matching closing delimiters.

Bad:

```asciidoc
====
content
```

Good:

```asciidoc
====
content
====
```

Rationale: unterminated blocks can cause large portions of a document to render
as the wrong block type. AD003 is a stable asciidoclint wrapper around the
native Asciidoctor diagnostic, not a duplicate parser implemented in the
tolerant source scanner.

Parser ownership: Asciidoctor owns delimited-block parsing and emits native
unterminated-block diagnostics for the supported delimited block contexts. AD003
matches those native diagnostics instead of maintaining its own delimiter
grammar.
