# AD022 - circular-include

Tags: core, includes, structure
Severity: error
Fixability: no.
Fix helper: Remove one include from the reported cycle, or replace one edge with an xref or a smaller shared partial that does not include its parent.

Description: Include trees must not contain cycles.

Necessity: The include directive is a preprocessor directive. Asciidoctor replaces the directive with the target file's lines before parsing document structure, and nested AsciiDoc includes are processed recursively. A cycle means the document graph cannot be expanded as intended.

Rationale: Asciidoctor has a `max-include-depth` safeguard and eventually emits a depth-limit diagnostic for a circular graph, but that diagnostic does not identify the cycle edge directly. `AD022` reports the cycle as document-graph structure so the author can fix the include relationship instead of debugging repeated expansion output.

Bad:

What's wrong: `doc.adoc` includes `a.adoc`, and `a.adoc` includes `doc.adoc` again. The graph has no acyclic expansion order.

```adoc
include::a.adoc[]
// a.adoc includes this file again
```

Good:

Expected: Included files do not include the parent document or otherwise point back to an ancestor.

```adoc
include::chapter.adoc[]

include::appendix.adoc[]
```

Implementation note: `AD022` uses the normalized include graph, not an independent raw include parser. That graph already applies attribute substitution, resolves include targets relative to the including file, records source locations, and only descends into files treated as AsciiDoc sources by the parser. The rule intentionally does not enforce a house-style maximum include depth; projects that want a shallow hierarchy limit should implement that as a custom rule.
