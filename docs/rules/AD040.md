# AD040 - html-link-text-residue

Tags: cleanup, links, conversion
Severity: warning
Fixability: no.
Fix helper: Keep only the intended human-readable link text and remove raw
markup fragments from the label.

Necessity: Asciidoctor allows passthroughs and raw backend markup in some
contexts, but raw HTML/XML-looking fragments inside `link:` or `xref:` label
text are escaped and become visible label text. That is usually conversion
residue, and the rendered link label is noisy or misleading.

Parser ownership: Asciidoctor.js is the rendering baseline and does not emit a
diagnostic for this case. AD040 uses a narrow source scanner for `link:` and
`xref:` macro labels containing raw tag-like fragments such as `<span>` or
`++<span>...++`. It skips line comments, comment paragraphs, and protected
blocks. It does not report punctuation passthrough cleanup handled by AD039, or
nested link/xref labels handled by AD031.

Link text should not contain raw HTML or XML residue.

Bad:

```adoc
link:https://example.com[++<span>Example</span>++]
```

What's wrong: Asciidoctor renders the link label as visible escaped markup, not
as a clean `Example` label.

Good:

```adoc
link:https://example.com[Example]
```

Expected: The link label contains only the text readers should see.

Allowed:

```adoc
link:https://example.com[DEVICE++_++STATUS]
link:https://example.com[all-natural++*++]
```

Rendering rationale: raw tag-like text inside a link label is displayed to the
reader. Removing the tags is an author decision because the intended label may
be the tag content, an adjacent word, or a rewritten phrase.
