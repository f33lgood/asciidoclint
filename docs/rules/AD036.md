# AD036 - list-marker-residue

Tags: cleanup, lists
Severity: warning
Fixability: no.
Fix helper: Remove the marker residue, add the missing list item text, or use
`{empty}` plus a list continuation when the list item intentionally has only
attached block content.

Necessity: Asciidoctor requires a list item's principal text to be offset from
the marker by at least one space. A line that contains only `*`, `**`, `-`, `.`,
`..`, or `10.` is not an empty list item; it renders as visible paragraph text
or gets absorbed into nearby paragraph content. That is usually conversion
residue or unfinished authoring.

Parser ownership: Asciidoctor.js is the behavior baseline and does not emit a
diagnostic for marker-only residue. AD036 uses a narrow source scanner for
documented unordered and ordered list marker spellings, skips protected blocks
and table bodies, and excludes real block delimiters such as `....` and `----`.

Standalone list marker residue should be removed or completed.

Bad:

```adoc
*
Text
```

This renders as paragraph text containing a visible `*`, not as a list item.

Good:

```adoc
* Text
```

When a list item intentionally has no principal text and only attached block
content, use Asciidoctor's documented `{empty}` pattern with a list continuation:

```adoc
. {empty}
+
----
print("one")
----
```

Rendering rationale: marker-only residue does not create a reliable list item.
It either appears visibly in the output or becomes paragraph content, so the
reader sees a broken list artifact.
