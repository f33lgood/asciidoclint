# AD004 - table-cell-count

Tags: `core`, `table`
Severity: warning
Fixability: no.
Fix helper: Add missing table cells, remove leftover cells, or make intended row and column spans explicit so every source cell appears in the rendered table.

Necessity: Asciidoctor accepts table cell streams and derives rows from the order of cell separators, the declared column count, and any row or column spans. Cells may be written on the same source line or consecutive source lines. However, if the stream ends with an incomplete row, Asciidoctor can omit the leftover source cells without reporting a parser diagnostic. The table renders, but source data is missing from the visible output.


Table source should not contain cells omitted from rendered output.

Bad:

```asciidoc
[cols="1,1"]
|===
| one | two | omitted
|===
```

What's wrong: The table declares two columns but provides three cells. Asciidoctor
renders the complete row and omits the leftover cell.

Good:

```asciidoc
[cols="1,1"]
|===
| one | two
|===
```

Expected: All source cells appear in the rendered table. Additional rows should
provide enough cells to complete the row, accounting for row and column spans.

Rationale: this rule is not a generic "one source line equals one table row"
style check. Asciidoctor explicitly allows cells in a row to be written on the
same line or consecutive lines. AD004 only reports the conservative case where
Asciidoctor's parsed table contains fewer rendered cells than the source cell
stream, which indicates omitted table data.

Implementation note: table boundaries should come from Asciidoctor.js table
spans, and rendered cell counts should come from Asciidoctor.js table rows. AD004
may inspect source lines inside those spans because Asciidoctor does not report
omitted-cell diagnostics, but the tolerant parser must not be the authority for
deciding where tables start and end. Tables with explicit row spans or column
spans are supported as long as Asciidoctor renders every source cell. The rule
skips non-default table separators and nested default-PSV table delimiters until
the Asciidoctor table model exposes enough source mapping for those cases.

Parser ownership: Asciidoctor owns table recognition, table spans, and rendered
cell counts. AD004 only source-scans inside those Asciidoctor-owned spans to
detect source cells that did not survive into the rendered table model.
