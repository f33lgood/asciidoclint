# AD008 - blank-before-list

Tags: `core`, `lists`, `blank_lines`
Severity: warning
Fixability: safe.
Fix helper: Insert one blank line before the list marker. This is the safe automatic fix emitted by asciidoclint.

Necessity: Asciidoctor documents that empty lines are required before and after a list to separate it from other blocks. When paragraph text is immediately followed by a list marker, Asciidoctor treats the marker line as more paragraph text and the intended list is not created.


Lists should be separated from preceding paragraph text. AD008 covers common
AsciiDoc unordered, ordered, and description list markers.


Bad:

```asciidoc
Paragraph
* item
```

Good:

```asciidoc
Paragraph

* item
```

Rationale: the missing blank line changes the rendered block structure, so this
is more than source-format style. The safe automatic fix inserts a blank line
before the first list item.

Implementation notes: AD008 only checks a list marker that follows paragraph-like
content. It does not report list markers after structural lines such as section
titles, block titles, anchors, attribute lines, other list items, list
continuations, or inside protected/table blocks.

The scanner recognizes unordered list markers (`*`, `**`, `-`), ordered list
markers (`.`, `..`, `1.`), and description list delimiters (`::`, `:::`,
`::::`, `;;`). Callout lists (`<1>`) are not part of AD008 because they depend
on nearby verbatim callout references and Asciidoctor can warn when that context
is missing.

Parser ownership: AD008 must source-scan because the missing separator causes
the would-be list marker to be parsed as paragraph text, leaving no list block in
the Asciidoctor AST to inspect. The scanner therefore documents and tests the
list marker variants it recognizes.
