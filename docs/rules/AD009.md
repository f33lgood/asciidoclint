# AD009 - blank-after-list

Tags: `core`, `lists`, `blank_lines`, `structure`
Severity: error for section titles; warning for other structural starts
Fixability: safe.
Fix helper: Insert one blank line before the structural line that follows the list.

Necessity: A section title, anchor, block title, or block image macro immediately after list content can be parsed as text inside the previous list item. The intended section, figure title, anchor target, or image then disappears from the rendered structure.


Lists should be separated from following structural blocks.


Bad:

```asciidoc
* item
== Next section
```

What's wrong: Asciidoctor treats the section-title-looking line as list-item
paragraph text, so `Next section` is not created in the document outline.

Good:

```asciidoc
* item

== Next section
```

Expected: The blank line closes the list before the section title, so the
following line renders as a section.

Rationale: This pairs with AD008. AD008 catches a missing blank before a list
marker; AD009 catches a missing blank after list content when the next line is a
structural block start that can otherwise be swallowed by the list item.

AsciiDoc/Asciidoctor basis: Asciidoctor list items may contain continuation
text and attached blocks. Without a separating blank line, following structural
source lines can be interpreted as part of the list item rather than as new
top-level document structure.

Asciidoctor.js behavior: Local rendering confirms that `* item` followed
immediately by `== Next section` renders the section syntax inside the list
item paragraph and does not emit an `<h2>` section heading. Similar immediate
block titles, anchors, and block image macros can be swallowed instead of
creating the intended titled block or image.

Parser ownership: AD009 uses a source scanner because the linter needs to
identify the author's intended structural line before Asciidoctor has already
absorbed it into list text. The rule skips protected blocks and table bodies,
allows nested list style attributes before nested list markers, and allows
intentional list continuations marked with `+`.

Implementation note: AD009 reports the first structural line swallowed after a
list item and avoids cascading reports for the image or table line that follows
an already-reported title or anchor. The safe fix inserts a single blank line
before the reported structural line.
