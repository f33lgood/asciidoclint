# AD034 - no-hard-tabs

Tags: `cleanup`, `whitespace`
Severity: warning
Fixability: safe.
Fix helper: Replace hard tabs in prose or structural markup with spaces. Keep tabs inside TSV tables and protected/verbatim content when they are intentional data.

Necessity: Asciidoctor accepts tabs, so a hard tab is not invalid AsciiDoc.
However, hard tabs in prose and structural markup are rendered and displayed
with environment-dependent widths. Asciidoctor also treats tabs specially in
some contexts, such as `tabsize` processing for verbatim content and tab
separators in TSV tables. AD034 therefore only reports tabs in ordinary source
lines where replacing a tab with a space is a deterministic cleanup.

Parser ownership: Asciidoctor.js is the behavior baseline and does not report
hard tabs as diagnostics. AD034 uses a narrow source scan and intentionally
skips protected/verbatim blocks and table bodies, where tabs may be meaningful
content or syntax.

Ordinary prose and structural markup lines should not contain hard tabs.


Bad:

```asciidoc
*	Tabbed list item
```

Good:

```asciidoc
* Tabbed list item
```

Allowed:

```asciidoc
[%header,format=tsv]
|===
Name	Value
Alpha	1
|===
```

Rationale: hard tabs in normal text and markup render inconsistently across
editors, terminals, and generated output. Tabs inside TSV tables, listing,
literal, source, passthrough, stem, diagram, and comment blocks are outside this
rule because they can be intentional data.
