# AD030 - markdown-table-residue

Tags: conversion, table
Severity: warning
Fixability: no.
Fix helper: Rewrite the Markdown pipe table as an AsciiDoc table delimited by `|===` and verify column structure manually.

Necessity: Markdown pipe table separator lines render as paragraph text in AsciiDoc, not as a table delimiter. The intended table is lost.


Markdown pipe table residue should not render as text.

Bad:

```adoc
| A | B |
|---|---|
```

Good:

```adoc
|===
| A | B
|===
```

AsciiDoc/Asciidoctor basis: Asciidoctor documents Markdown-compatible syntax as
an optional feature. The documented compatible forms include Markdown-style
headings, fenced code blocks, blockquotes, and thematic breaks, but not
Markdown pipe tables.

Asciidoctor.js behavior: A Markdown pipe table such as the bad example renders
as paragraph text and does not create a `<table>` in HTML output.

Parser ownership: AD030 is a narrow source scanner for Markdown pipe table
separator lines. Asciidoctor preserves the source as paragraph text and does not
emit a diagnostic for the lost table intent.

Implementation note: AD030 skips protected blocks and real AsciiDoc table
blocks. A line such as `|---|---|` inside a `|===` table can be ordinary table
cell content and is not reported.
